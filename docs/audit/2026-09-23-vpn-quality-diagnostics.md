# Проверка качества VPN — 23 сентября 2026

Основные прогоны начались в 11:53 и 11:54 МСК. Точки запуска — входные серверы профилей Литва (45.91.52.204) и Германия (158.160.188.35); названия профилей не означают физическую страну точки запуска. Это серверные сети, не домашние и мобильные провайдеры пользователей.

## Методика

На каждый из 13 профилей выполнено по 5 HTTPS-запросов с каждой точки к Cloudflare trace и по одному скачиванию 2 000 000 байт с каждой точки. Скачивания последовательные, без параллельного насыщения каналов; таймаут 15 секунд, предел размера 2 100 000 байт. Итого 130 коротких запросов и 26 скачиваний через VPN, 52 МБ полезных данных скачивания. Два контрольных скачивания без VPN добавили 4 МБ. Дополнительно 15 запросов через литовские профили к Google gstatic.

Использован существующий активный ключ: активного внутреннего тестового аккаунта не оказалось. Ключи и подписки не изменялись; тестовый трафик может учитываться в статистике использованного аккаунта. Временные процессы Xray и конфиги удалены после каждого профиля. Основные процессы не перезапускались.

Установление — время от начала запроса до завершения TLS целевого сайта через VPN (curl time_appconnect), не изолированный handshake VLESS. Каждый curl создаёт новое HTTPS-соединение; Xray работает на протяжении серии и может переиспользовать транспорт. Отклик — время до первого байта (TTFB), включает установление и обработку сервером. Колебания — стандартное отклонение TTFB по 10 запросам; это не измерение пакетного jitter/ICMP RTT. Скорость — полезные байты / полное время запроса, включая установление; короткий тест не показывает предельную пропускную способность.

Контроль без VPN: 46,1 и 51,5 Мбит/с на таком же файле.

## Выводы

Все профили доступны из двух проверенных сетей. Приоритет диагностики — пятисекундные задержки на литовских направлениях к Cloudflare, затем малая эффективная скорость коротких скачиваний через США и повторные передачи TCP на финском входе. Признаков ошибок/drop сетевых интерфейсов в этом окне нет. Для выводов о вечерней нагрузке, мобильных сетях и скорости пользователей нужны отдельные точки и более длинное окно.

Описание метрик curl: https://curl.se/docs/manpage.html

## Последующая локализация

Все действия ниже — диагностика без изменения сетевых настроек и перезапуска основных процессов.

### Литва

- 36 HTTPS-запросов непосредственно через межсерверный outbound литовского входа: два назначения, hostname / явный IPv4 / явный IPv6, по шесть запросов. Все успешны, пятисекундных пауз нет. Прямой маршрут Google во входном конфиге в этой изолированной проверке не использовался.
- Дополнительно 45 HTTPS-запросов через полный профиль «Литва 1.0» к Cloudflare: по 15 для hostname / явного IPv4 / явного IPv6. Все успешны; максимальный TTFB 594 мс, паузы не воспроизвелись.
- 30 вызовов системного getaddrinfo на входе: 4–10 мс. 60 отдельных UDP DNS-запросов A/AAAA к трём настроенным резолверам: ошибок и таймаутов нет; максимум 406 мс.
- Полученный SSH host key зарубежного выхода не совпадает с ранее доверенным на сервере приложения. Проверка host key не отключалась, known_hosts на сервере приложения не изменялся. Прямое администрирование выхода отложено до независимого подтверждения владельцем.
- Постоянный дефект DNS/IPv6 не подтверждён. До получения воспроизводимого сбоя принудительно менять семейство IP или резолверы не следует.

### Финляндия

- Повторный системный замер: 3283 повторных TCP-сегмента / 100519 исходящих за 139,68 секунды, около 3,27%.
- По изменениям TCP_INFO удалось отнести минимум 2576 повторов (78,46% общесистемного числа) к клиентской стороне входа и 19 — к зарубежным выходам. Метод не учитывает закрывшиеся между снимками соединения; неатрибутированный остаток сохраняется.
- В отдельном 30-секундном окне 95,17% учитываемых повторов дали два клиентских адреса. Адреса не сохранялись. Это направление TCP, не доказательство аутентификации конкретного VPN-пользователя.
- CPU около 10%, available RAM 2,41 ГБ, новых qdisc drops нет. BBR уже используется, включая исследованные XHTTP-соединения.
- Около 10,7 тысячи XHTTP-сокетов, из них около 10,4 тысячи без активности более часа. Повторный снимок: общее число снизилось с 10703 до 10583, idle более часа практически не изменилось (10445 → 10446).
- Xray использует 10865 FD из лимита 524287 (около 2,1%), RSS 881 MiB при возрасте процесса 11,7 суток. Исчерпание ресурсов и утечка не подтверждены. Нельзя считать число сокетов количеством пользователей.
- Перенос зарубежного выхода, массовое закрытие соединений и изменение TCP-настроек текущими измерениями не обоснованы. Приоритет дальнейшего наблюдения — концентрация повторов по клиентским направлениям и динамика FD/RSS/idle.

### США: размер теста влияет на результат

Запрос 16 МБ тестовый сервис отклонил HTTP 403, в том числе без VPN; эти ответы исключены из оценки скорости. При разрешённом размере 10 МБ все четыре скачивания успешны:

|---|---:|---:|
| Без VPN с измерительной точки | 0,383 | 209,1 |
| Германия 1.0 | 0,663 | 120,7 |
| США 1.0 | 4,901 | 16,3 |

Изолированный межсерверный outbound с входного сервера США: 10 МБ за 3,432 с (23,3 Мбит/с); контроль без этого outbound с той же точки — 208,5 Мбит/с. Это другая измерительная точка, поэтому значения нельзя напрямую вычитать из предыдущей таблицы.

Это по одному дополнительному скачиванию на маршрут, не устойчивый предел полосы. Первоначальные 4–10 Мбит/с на 2 МБ нельзя интерпретировать как ограничение канала США. Межконтинентальная задержка остаётся заметной.

### Что уже есть для мониторинга

- StatsService-сбор подтверждает доступность статистики, не качество пользовательского туннеля; хранится последнее наблюдение.
- Клиентский `/check` уже реализован, но CONNECTION_CHECK_ENABLE выключен; за последние семь дней записей нет.
- `/check` измеряет браузер → API сервиса, может использовать прямой маршрут и существующее HTTPS-соединение. connected определяется по адресу POST результата. Это не доля успеха всех VPN-подключений; полностью не дошедшие запросы не сохраняются.
- Для регулярных synthetic нужны отдельная служебная identity на точку, запрет fallback на аккаунты клиентов, история, ограниченные HTTPS-пробы и явное разделение серверных и пользовательских измерений.
- Стандартного операторского создания service account нет; web-only identity уже использует отрицательный ID из последовательности. is_internal сам по себе является аналитическим флагом, а не служебной ролью.

## Дальнейшие работы

1. Подтвердить SSH host key литовского выхода независимым каналом; затем проверить его DNS/сетевые счётчики при воспроизведении паузы.
2. Сохранить раздельные метрики клиентского и межсерверного участков Финляндии, без сбора пользовательских адресов в отчёты.
3. Внедрять регулярный мониторинг отдельным MR, со служебной identity и измерением реального маршрута, без автоматического изменения VPN-конфигурации.
4. Изменение автовыбора или сравнительный эксперимент BBR выполнять только после получения сопоставимых исходных измерений. BBR на Финляндии уже включён.

Официальные описания: [TCP-счётчики Linux](https://docs.kernel.org/networking/snmp_counter.html), [XHTTP/XMUX](https://github.com/XTLS/Xray-core/discussions/4113).

# Plan — Вход по ссылке-подписке вместо email-авторизации

- **Дата:** 2026-09-20
- **Spec:** `docs/superpowers/specs/2026-09-20-link-auth-design.md`
- **Ветки:** 7 короткоживущих веток (MR1–MR7, см. фазы) — TBD: одна задача = одна ветка = один MR

## Сводка

Заменяем email+OTP вход и JWT-куки на Bearer-авторизацию по `subscription_token`; добавляем
эндпоинт выдачи ссылки по почте (почта не хранится), переписываем фронтенд на in-memory токен,
добавляем привязку ссылки в боте (восстановленный account_merge по токену), прощальной рассылкой
мигрируем оставшихся web-юзеров и дропаем таблицы почт. 7 MR-фаз.

- **Acceptance:** поведение провайдера не изменилось (`/sub/`-тесты зелёные); функцию можно

### Задача 1.2 — `send_subscription_link`
- **Файлы:** `backend/src/app/email/sender.py`
- **Что сделать:** новая функция по образцу `send_verification_code`: branded HTML с кнопкой +

### Задача 1.3 — роут `POST /api/v1/auth/link/request`
- **Файлы:** `backend/src/app/web_api/link_auth.py` (новый), `backend/src/app/web_api/app.py`
- **Что сделать:** валидация email (`helpers.validate_email`) + disposable (`is_disposable_email`,

- **Коммит:** «feat(web): эндпоинт выдачи ссылки-подписки по email»

## Фаза 2 (MR2) — `feat/web-token-auth`: Bearer-токен (dual-mode)

### Задача 2.1 — `require_auth` принимает токен подписки
- **Файлы:** `backend/src/app/web_api/middleware.py`
- **Что сделать:** при `Authorization: Bearer <token>` — lookup `user_identities.subscription_token`
  (без entitlement-гейта), identity в request.state; без Authorization — прежний JWT-путь с CSRF.
  Rate-limit неудачных токенов (per-IP). Сохранить `check_jwt_not_revoked`, `generate_csrf_token`.
- **Acceptance:** Bearer-токен проходит на `/api/v1/user/profile`; неизвестный → 401; истёкшая
  подписка → 200; legacy-JWT жив; админ-импорты целы.

### Задача 2.2 — `login_url` в профиле
- **Файлы:** `backend/src/app/web_api/profile.py` (SELECT `:58-79`, сборка ответа)
- **Что сделать:** добавить `subscription_token` в SELECT; ответ содержит `subscription_url` и
  `login_url` (`{site}/auth/<token>`).
- **Acceptance:** профиль отдаёт обе ссылки (критично: без этого первый выход = лок-аут).
- **Коммит:** «feat(web): вход по Bearer-токену подписки (наряду с JWT)»

## Риски и откат

- Миграции авто-применяются при деплое → жёсткий порядок: срезка → рассылка (OPS-пауза ≥72ч) → дроп.
- Dual-mode (MR2–MR4) не ломает платежи и админку; откат каждого MR — revert MR.
- Первый выход без копирования ссылки = лок-аут → закрывает `login_url` в профиле + блок на дашборде.
- GitLab: обычный push/MR-флоу; CI-статус проверять ≤2–3 раза после push (лимит CI-минут).

# План: регулярные проверки качества VPN

- Spec: `docs/superpowers/specs/2026-09-23-vpn-quality-monitor-design.md`
- Ветка: `feat/vpn-quality-monitor`

1. Добавить аддитивную миграцию реестра/запусков/проб; bootstrap служебной identity с
   отрицательным ID и атомарным однократным grant. Проверить повторный запуск и истечение.
2. Реализовать изолированный ограниченный HTTPS probe и collector без выбора пользовательских
   ключей, с сериализацией только безопасных результатов и гарантированным cleanup.
3. Добавить читающий admin API и блок качества на странице серверов, историю и свежесть.
4. Добавить unit, PostgreSQL и UI-тесты; прогнать полный backend, frontend и обязательные гейты.
5. Независимый review, отдельный MR, зелёный CI, merge и deploy. Включить одну измерительную
   точку только после проверки новой identity и ручного цикла. Проверить пользователей после.

Риск: ошибка measurement host или неполная карта выходов не должны отображаться падением VPN.
Повтор bootstrap не продлевает доступ. Ошибка provisioning не заставляет создавать второй аккаунт.
Отмена collector и SSH-сбой ограничены timeout; временные credentials не попадают в логи.
Откат выключает только новый systemd timer/точку, без восстановления старого Xray-конфига.

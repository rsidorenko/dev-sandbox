# Plan — быстрый путь от триала до подключения

- **Дата:** 2026-09-11
- **Spec:** `docs/superpowers/specs/2026-09-11-trial-connect-fastpath-design.md`
- **Ветка:** `feat/trial-connect-fastpath`

## Сводка

Аддитивно вводим одноэкранный путь подключения для основных платформ, направляем в него
пользователя сразу после триала и сохраняем старые пошаговые инструкции как fallback.

## Фаза 1 — интерфейс fast path

### Задача 1.1 — добавить callbacks, тексты и клавиатуры
- **Файлы:** `backend/src/app/bot_transport/storefront_ui.py`.
- **Что сделать:** добавить отдельные fast callback-коды, компактные инструкции, кнопки
  установки/copy/import/result и переход к существующей подробной инструкции.
- **Acceptance:** четыре основные платформы рендерятся без пустых URL; старые callback-коды и
  пошаговые функции не изменяют контракт.

### Задача 1.2 — сократить экран после триала
- **Файлы:** `backend/src/app/bot_transport/storefront_ui.py`,
  `backend/src/app/bot_transport/runtime_facade.py`.
- **Что сделать:** после успешной выдачи триала показать прямой выбор устройства; основной экран
  выбора тоже направить в fast path.
- **Acceptance:** новый пользователь начинает настройку одним нажатием после активации, а главное
  меню остаётся доступно.

## Фаза 2 — безопасная маршрутизация и аналитика

### Задача 2.1 — получить конфиг и отрендерить fast path
- **Файлы:** `backend/src/app/bot_transport/runtime_facade.py`.
- **Что сделать:** распознать новые callbacks, проверить entitlement, получить персональный
  subscription URL и вернуть безопасный fallback при отсутствии конфига.
- **Acceptance:** токен не передаётся в callback; keyless/expired пользователь не получает кнопку
  импорта.

### Задача 2.2 — сохранить измеримость
- **Файлы:** `backend/src/app/application/funnel_events.py`.
- **Что сделать:** сопоставить fast callbacks событию `platform_selected`.
- **Acceptance:** аналитика одинаково считает выбор платформы в коротком и подробном пути.

## Фаза 3 — проверки и MR

### Задача 3.1 — покрыть сценарии тестами
- **Файлы:** `backend/tests/test_trial_connect_fastpath.py`,
  `backend/tests/test_funnel_foundation.py`.
- **Acceptance:** проверены экран после триала, четыре fast path, copy/import, подробный fallback,
  подтверждение результата и keyless-защита.

### Задача 3.2 — выполнить delivery
- **Файлы:** только файлы этой фичи.
- **Acceptance:** точечные и полные тесты, Ruff, health-check и `git diff --check` зелёные; создан
  GitLab MR без автоматического слияния.

## Стратегия тестирования

- Чистые unit-тесты UI проверяют структуру клавиатур и отсутствие токена в callback_data.
- Facade-тесты на `StubVlessProvider` проходят настоящий `/start → trial → fast callback`.
- Негативный facade-тест проверяет пользователя без активной подписки.
- Полный backend pytest и release health-check исключают регрессии старого сценария.

## Риски и откат

- `copy_text` может не поддерживаться старым Telegram-клиентом: URL остаётся видимым в
  `<code>`, а подробная инструкция доступна отдельной кнопкой.
- App Store/Play Store/GitHub недоступен: пользователь может перейти в подробный сценарий или
  поддержку.
- Откат приложения полностью возвращает старую маршрутизацию; миграций и данных для отката нет.

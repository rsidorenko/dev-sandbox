# Проверки перед production-деплоем

- Дата: 2026-09-22
- Статус: reviewed
- Основание: поручение проверить аудит и довести подтверждённые исправления до MR/merge.
- План: `docs/superpowers/plans/2026-09-22-deploy-validation-gate.md`

## Проблема и подтверждение

В `.gitlab-ci.yml` у `deploy` задано `needs: []`: стадия deploy не ждёт тестов.
Ошибка завершающего curl подавляется через `|| true`. Отдельной проверки готовности
в `scripts/ci/deploy_remote.sh` нет. Два pipeline могут одновременно заменять один каталог.

## Решение и границы

Убрать обход стадий, сериализовать деплой через `resource_group: production`,
разрешать его только для main. Вынести проверку HTTP healthz в небольшой скрипт
с ограниченными повторами и ненулевым кодом выхода при недоступности. Сбой SSH
также должен завершать job ошибкой. Автоматический откат и перестройка сборки
образов не входят в этот фикс: без отдельного дизайна миграций откат небезопасен.

## Влияние и приёмка

Нет миграций, изменений платежей и VPN-доступа. Деплой начнётся позже, после CI.
При успешном healthcheck код выхода 0, при постоянном отказе — 1; временный отказ
переживается повтором. Ожидание ограничено. Все обязательные стадии сохраняются.
Проверки: исполняемые тесты healthcheck с подставным curl, pytest, ruff,
проверка конфигурации GitLab, review и зелёный MR pipeline перед merge.

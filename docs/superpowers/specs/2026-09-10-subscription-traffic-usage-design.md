# Design Spec — Расход трафика в карточке подписки

- **Автор / ответственный:** команда Bravada VPN
- **Дата:** 2026-09-10
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-10-subscription-traffic-usage.md`

## Контекст и проблема

VPN-клиент Happ показывает в карточке подписки данные стандартного заголовка
`subscription-userinfo`. Сейчас endpoint `/sub/{token}` отдаёт в нём
`upload=0; download=0; total=0`, поэтому пользователь всегда видит `0 Б/∞`,
даже когда уже пользовался VPN.

Сбор фактического трафика bare Xray уже сохраняет входящий и исходящий трафик
пользователя по дням. Нужно передавать эти накопленные значения клиенту, не
меняя модель безлимитной подписки.

## Цели

- Показывать в карточке подписки фактически израсходованный трафик текущего
  московского месяца.
- Сохранить безлимитный лимит: клиент должен отображать объём как
  «израсходовано / ∞».
- Не выполнять дополнительный запрос к БД, когда метаданные профиля выключены.

## Non-goals

- Не вводить лимиты трафика, биллинг по байтам или изменение тарифов.
- Не менять сбор, атрибуцию и хранение счётчиков Xray.
- Не добавлять миграции и не менять исторические данные.

## Текущее состояние

- `backend/src/app/web_api/subscription.py` (`handle_subscription`,
  `_profile_meta_headers`) формирует `subscription-userinfo`, но обнуляет
  `upload` и `download`.
- `backend/src/app/persistence/postgres_traffic_stats.py`
  (`PostgresTrafficStatsRepository`) хранит и читает месячные дельты
  пользовательского upload/download из `bare_xray_traffic_daily`.
- `backend/src/app/issuance/bare_xray_traffic.py` определяет московские
  календарные границы, используемые учётом трафика.

## Предлагаемое решение

Добавить в репозиторий статистики метод чтения суммарных upload/download за
текущий московский месяц. При включённом `SUB_PROFILE_META_ENABLE` endpoint
`/sub/{token}` прочитает эти два значения для владельца токена и передаст их в
`_profile_meta_headers`. Заголовок получит вид
`upload=<байты>; download=<байты>; total=0; expire=<unix-время>`.

Нулевой `total` остаётся контрактом безлимитной подписки; если статистика ещё
не собрана, оба значения безопасно равны нулю.

## Альтернативы

- Передавать только общий объём в `download` — отклонено: стандартный заголовок
  различает направления, и это исказило бы статистику.
- Считать трафик непосредственно из Xray на запрос `/sub/` — отклонено: это
  сделает публичный endpoint зависимым от сети серверов и повысит его задержку.
- Хранить всё время подписки вместо месяца — отклонено: в проекте уже есть
  проверенная месячная агрегация, а новая схема потребовала бы миграции и
  определения точки сброса при продлении.

## Влияние

- **Файлы:** `backend/src/app/persistence/postgres_traffic_stats.py`,
  `backend/src/app/web_api/subscription.py` и их тесты.
- **Миграции БД:** не нужны; используется существующая миграция 079.
- **Безопасность:** endpoint продолжает использовать токен подписки; новые
  данные относятся только к владельцу токена и не содержат секретов.
- **Биллинг:** не затрагивается.
- **Retention / lifecycle:** не затрагивается.
- **VPN-провайдер:** не затрагивается; используются уже собранные данные.

## Открытые вопросы

Нет.

## Критерии приёмки

- [ ] При включённых метаданных `/sub/{token}` передаёт фактические месячные
  upload/download в `subscription-userinfo`.
- [ ] `total=0` сохраняется, поэтому карточка остаётся безлимитной.
- [ ] При отсутствии данных передаются нули без ошибки.
- [ ] Тесты покрывают чтение статистики и формирование заголовка.
- [ ] `pytest -q` зелёный, `python scripts/run_mvp_repo_release_health_check.py` проходит.

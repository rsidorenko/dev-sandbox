# Сохранение начала подключения при переносе часов триала

- Дата: 2026-09-25
- Статус: approved — автономная реализация подтверждённых улучшений по поручению пользователя.
- План: `docs/superpowers/plans/2026-09-25-trial-onboarding-anchor.md`

## Проблема

Collector `PostgresTrafficStatsRepository.apply_batch` переносит trial_started_at
на первое подключение. SQL аналитики и напоминаний ищет выбор платформы и маршрут
после trial_started_at, поэтому теряет предыдущие шаги установки. Это не доказывает
отсутствие действий пользователя и искажает диагноз воронки.

## Решение

Nullable trial_provisioned_at сохраняет время выдачи. Первичный snapshot upsert и
collector сохраняют его, последующие записи не переносят. Миграция восстанавливает
только строки без первого трафика, где исходное начало ещё достоверно. Для legacy
с уже перенесённым clock значение остаётся неизвестным, отчёт показывает счётчик
таких записей; при неизвестности сохраняется прежняя консервативная граница.

Onboarding-события фильтруются от COALESCE(trial_provisioned_at, trial_started_at).
Рекламные события дополнительно ограничены временем атрибуции. Срок триала, retention,
D1–D3 и 10-дневная зрелость по-прежнему используют trial_started_at. Частота и количество
напоминаний не меняются, исправляется только определение платформы/контекста checkout.

## Приёмка и границы

Аддитивная миграция 105. Без изменений доменного SubscriptionSnapshot, оплаты,
VPN-ключей и длительности триала. PostgreSQL regression: выдача → выбор платформы
→ первый трафик → отчёт сохраняет маршрут; повтор collector/upsert не сдвигает anchor;
legacy неизвестность не превращается в выдуманную дату. Полный pytest, ruff, CI, review,
merge и post-deploy smoke. Откат кода безопасен при сохранении новой колонки.

# Design Spec — Обратная связь по триалу

- **Автор / ответственный:** команда Bravada VPN
- **Дата:** 2026-09-19
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-19-trial-feedback.md`

## Контекст и проблема

Текущая аналитика показывает, что пользователь сообщил о проблеме подключения или не оплатил
триал, но не объясняет причину. Поддержка видит только агрегированный отвал, поэтому невозможно
отделить техническую проблему от сложности инструкции, цены или отсутствия потребности.

## Цели

- Ненавязчиво спросить причину после нажатия «Не получилось» в direct и guided сценариях.
- Добавить вопрос о причине неоплаты в follow-up после завершения триала.
- Всегда позволять пропустить вопрос и продолжить прежний сценарий без дополнительного барьера.
- Хранить только закрытые reason-коды, платформу и маршрут; не собирать свободный текст.
- Показать агрегаты причин в API и текущей админке с исключением internal/nakrut пользователей.

## Non-goals

- Не менять длительность триала, тарифы, оплату, VPN-конфигурацию или уведомления по времени.
- Не открывать чат со свободным текстом и не создавать тикеты поддержки автоматически.
- Не выполнять автоматическую диагностику соединения — это следующая фича.

## Предлагаемое решение

Добавляется таблица `trial_feedback` с одной актуальной записью на пользователя, тип и платформу.
Поддерживаются типы `connection_problem` и `trial_nonpayment`. Повторный ответ обновляет reason и
контекст, поэтому повторное нажатие callback идемпотентно и не раздувает статистику.

После direct/guided кнопки проблемы бот сначала показывает короткий список причин. Ответ или
«Пропустить» ведёт на тот же экран восстановления, который существовал до фичи. Follow-up после
завершения триала получает вторую кнопку «Почему не подошло?»: после ответа остаются CTA оплаты и
помощи.

Recorder работает fail-open: ошибка/отсутствие таблицы логируется, но Telegram flow продолжает
работать. Callback принимает только серверный enum, длина остаётся ниже лимита Telegram.

## Причины

Проблема подключения: `install_failed`, `import_failed`, `connect_failed`, `traffic_failed`,
`too_hard`, `other`.

Неоплата: `too_expensive`, `did_not_work`, `too_hard`, `no_need`, `payment_issue`, `other`.

## Влияние

- **Миграция:** additive table, constraints и индекс по типу/времени.
- **Bot flow:** добавляется один необязательный экран; старый recovery screen сохраняется.
- **Биллинг/VPN:** не изменяются и не вызываются recorder-ом.
- **Privacy:** свободный текст и Telegram username не сохраняются.

## Критерии приёмки

- [x] Direct и guided проблемы предлагают причины и сохраняют route/platform.
- [x] Пропуск возвращает прежний recovery flow без записи feedback.
- [x] Follow-up неоплаты содержит survey CTA и корректно сохраняет reason.
- [x] Повторный ответ обновляет одну запись, миграция повторяема.
- [x] Ошибка записи не блокирует ответ бота.
- [x] Админка показывает распределение причин только eligible-пользователей.
- [x] Полные backend/frontend/release проверки зелёные.

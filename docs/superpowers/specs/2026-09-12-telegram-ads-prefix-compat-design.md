# Design Spec — совместимость рекламных start-меток

- **Автор:** rsidorenko
- **Дата:** 2026-09-12
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-12-telegram-ads-prefix-compat.md`
- **Ветка:** `fix/telegram-ads-prefix-compat`

## Контекст и проблема

Первая версия атрибуции распознаёт только Telegram start-параметры `tgads_*`, но часть уже
запущенной рекламы использует исторический префикс `ads_*`. Такие переходы проходят обычную
регистрацию, однако рекламный источник не записывается и отсутствует в отчёте.

## Цели

- Принимать оба публичных префикса: `tgads_` и `ads_`.
- Нормализовать оба формата в одинаковый `campaign_key` без префикса, чтобы одна кампания не
  распадалась на две строки отчёта.
- Сохранить first-touch, безопасную грамматику и независимость регистрации от аналитики.

## Non-goals

- Не восстанавливать переходы, потерянные до выпуска совместимости: исходных данных для этого нет.
- Не менять схему БД, отчёт, биллинг, триал или рекламные расходы.
- Не принимать произвольные префиксы: универсальность ограничена двумя реально используемыми
  контрактами, иначе обычные `/start`-параметры будут ошибочно считаться рекламой.

## Текущее состояние

- `backend/src/app/application/telegram_ads_attribution.py:13` задаёт единственный
  `_START_PREFIX = "tgads_"`; `parse_telegram_ads_campaign` отклоняет `ads_*`.
- `backend/src/app/bot_transport/normalized.py:186` передаёт сырой start-параметр этому парсеру;
  менять транспортный контракт не требуется.
- `backend/src/app/bot_transport/dispatcher.py:220` записывает уже нормализованный campaign key
  с first-touch семантикой.
- `backend/docs/telegram_ads_attribution.md` документирует только `tgads_*`.

## Предлагаемое решение

Заменить один префикс на фиксированный tuple `("tgads_", "ads_")`. Парсер после trim/lowercase
выбирает совпавший префикс, удаляет его и валидирует оставшийся campaign key существующим regex.
Оба входа `tgads_apk_01` и `ads_apk_01` возвращают `apk_01` и поэтому агрегируются вместе.

## Альтернативы

- Переписать активные объявления только на `tgads_*` — отклонено: уже размещённые ссылки
  продолжат терять атрибуцию, а их массовая замена не гарантирована.
- Хранить полный start-параметр с префиксом — отклонено: одинаковая кампания раздвоится в отчёте.
- Принимать любое значение после `ads` — отклонено из-за ложной атрибуции и высокой
  кардинальности.

## Влияние

- **Файлы:** parser, его unit/dispatcher tests и операторская документация.
- **Миграции БД:** нет.
- **Безопасность:** существующий regex и лимит 48 символов сохраняются.
- **Биллинг / VPN / retention:** не затрагиваются.

## Критерии приёмки

- [ ] `ads_<campaign>` и `tgads_<campaign>` возвращают одинаковый ключ.
- [ ] Case folding, длина, допустимые символы и отклонение `ref_*` не изменились.
- [ ] First-touch не перезаписывается при переходах между двумя префиксами.
- [ ] Документация содержит оба формата и правило канонизации.
- [ ] Полный backend pytest, Ruff и release health-check проходят.

# Design Spec — Терминальная ошибка Telegram 403

- **Автор / ответственный:** rsidorenko
- **Дата:** 2026-09-14
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-14-notification-terminal-403.md`

## Контекст и проблема

После сокращения cadence scheduler до 15 минут production показал повторные ответы Telegram
`403 Forbidden` для пользователей, заблокировавших бота. Сейчас неуспешная доставка не создаёт
дедуп-запись, поэтому заведомо недоставляемое уведомление повторяется до конца временного окна.

## Цели

- Прекратить повтор конкретного уведомления после Telegram 403.
- Сохранить ретраи для временных HTTP-ошибок, исключений и неуспешного веб-канала.
- Не учитывать терминальный отказ как успешную доставку.

## Non-goals

- Не отключать Telegram-пользователя глобально.
- Не менять тексты, расписание, оплату или VPN lifecycle.
- Не считать терминальными ответы 400, 429 и 5xx.

## Текущее состояние

- `backend/src/app/runtime/notification_scheduler.py:300` (`_send_notification`) пишет
  `notification_log` только после успешной доставки хотя бы в один канал.
- `backend/migrations/026_notification_state.sql` не различает успешную доставку и
  терминальное завершение попыток.

## Предлагаемое решение

Добавить additive-колонку `delivery_status` в `notification_log` со значениями `delivered` и
`terminal_failure`, сохранив `delivered` как default для обратной совместимости. При Telegram
403 scheduler пишет `terminal_failure`, только если другой доступный канал не был доставлен и
не завершился временной ошибкой. Успешный веб-канал остаётся `delivered`; ошибка веб-канала
вместе с Telegram 403 не закрывает уведомление и повторяется следующим тиком.

## Влияние

- **Миграции БД:** одна additive-колонка с безопасным default и идемпотентным CHECK.
- **Биллинг / VPN:** не затрагиваются.
- **Откат:** код можно откатить независимо; колонка совместима со старым кодом.

## Критерии приёмки

- [x] Telegram-only 403 пишет `terminal_failure` и возвращает `False`.
- [x] Telegram 400/429/5xx и исключения без другого канала не пишут дедуп.
- [x] Успешная веб-доставка при Telegram 403 пишет `delivered`.
- [x] Ошибка веб-доставки при Telegram 403 остаётся retryable.
- [x] Миграция повторяемая и проходит на PostgreSQL.

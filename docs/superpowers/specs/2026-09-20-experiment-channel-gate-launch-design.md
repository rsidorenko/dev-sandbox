# Design Spec — Управляемый запуск теста гейта канала

- **Автор / ответственный:** команда Bravada VPN
- **Дата:** 2026-09-20
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-20-experiment-channel-gate-launch.md`

## Контекст и проблема

В production зарегистрированы три продуктовых эксперимента. `checkout_reassurance_v1`
назначает варианты при каждом авторизованном открытии checkout и не имеет kill-switch,
тогда как `trial_channel_gate_v1` готов к запуску, но выключен. Одновременный запуск двух
тестов при текущем небольшом трафике затруднит интерпретацию оплаты и растянет набор выборки.

## Цели

- Сделать checkout-эксперимент opt-in и безопасно остановить новые назначения.
- Сохранить уже записанные назначения как неизменяемую историю.
- Подготовить `trial_channel_gate_v1` к единственному активному продуктовому тесту.
- Обеспечить быстрый откат обоих экспериментов переменными окружения.

## Non-goals

- Не удалять исторические назначения из `experiment_assignments`.
- Не менять цены, длительность триала, оплату, VPN-выдачу или уведомления.
- Не менять распределение `trial_channel_gate_v1` — остаётся детерминированное 50/50.

## Текущее состояние

- `backend/src/app/web_api/experiments.py:handle_resolve_experiment` сохраняет назначение
  `checkout_reassurance_v1` без проверки флага.
- `frontend/src/app/(site)/(protected)/payment/[planId]/page.tsx:PaymentForm` запрашивает
  назначение checkout при каждом авторизованном открытии страницы оплаты.
- `backend/src/app/application/trial_gate_experiment.py:resolve_trial_gate_variant` уже
  защищён `EXPERIMENT_CHANNEL_GATE_ENABLE` и при сбоях возвращает control.
- `docker-compose.prod.yml` передаёт channel-gate флаг с безопасным default `0`.

## Предлагаемое решение

Добавить `EXPERIMENT_CHECKOUT_REASSURANCE_ENABLE` с default `0`. Endpoint разрешения
эксперимента должен до записи назначения отклонять выключенный checkout-тест ответом
`experiment_disabled`; фронтенд уже безопасно остаётся в control при любом неуспешном ответе.

После зелёного CI и деплоя проверить runtime-флаги, явно оставить checkout выключенным и
включить `EXPERIMENT_CHANNEL_GATE_ENABLE=1`. Исторические строки не удаляются.

## Альтернативы

- Удалить checkout-тест из реестра: отклонено, потому что это ломает историческую аналитику
  и усложняет повторный запуск.
- Запустить оба теста одновременно: отклонено из-за малого трафика и смешения эффектов.

## Влияние

- **Файлы:** web API экспериментов, production compose, `.env.example`, тесты.
- **Миграции БД:** нет.
- **Безопасность:** новые публичные входы не добавляются; endpoint остаётся авторизованным и CSRF-защищённым.
- **Биллинг:** создание и применение платежей не меняются.
- **Retention / lifecycle:** без изменений.
- **VPN-провайдер:** без изменений.

## Открытые вопросы

Нет. Запуск согласован пользователем 2026-09-20.

## Критерии приёмки

- [ ] При выключенном checkout-флаге новые назначения не создаются, UI остаётся control.
- [ ] При включённом checkout-флаге существующее назначение 50/50 работает без изменений.
- [ ] Production compose передаёт оба флага с default `0`.
- [ ] После деплоя checkout выключен, channel-gate включён.
- [ ] Тесты backend/frontend и release health зелёные.

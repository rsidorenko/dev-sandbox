# Design Spec — Возврат в точный незавершённый заказ

- **Автор / ответственный:** rsidorenko
- **Дата:** 2026-09-16
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-16-exact-checkout-recovery.md`

## Контекст и проблема

Через 30 минут после незавершённого checkout пользователь получает напоминание, но кнопка ведёт в
общий каталог. Уже выбранные тариф, число устройств и способ оплаты теряются, поэтому пользователю
приходится повторять решения, принятые перед уходом.

## Цели

- Запоминать минимальный безопасный контекст заказа: тариф, устройства, способ и поверхность.
- В Telegram возвращать прямо в сводку того же заказа.
- В web-уведомлении давать ссылку на тот же `/payment/<plan>` с параметрами устройств и способа.
- Сохранить generic fallback для старых событий без контекста.

## Non-goals

- Не хранить URL провайдера, платёжные токены или секреты checkout.
- Не создавать платёж заранее и не обходить повторную server-side проверку цены/промокода.
- Не отправлять больше одного текущего напоминания на пользователя.

## Предлагаемое решение

Additive-миграция расширяет `funnel_interactions` nullable-полями `plan_id`, `device_count` и
`payment_method`. `record_interaction` принимает их после allowlist/range-валидации. Telegram
извлекает plan/device из callback `confirm_pay:<plan>:<devices>`; создание платежа в Telegram и web
пишет полный контекст, но не provider URL.

Scheduler выбирает последнее `checkout_opened` или `payment_created` в окне, формирует персональный
текст и callback `confirm_pay:<plan>:<devices>`. Для web в payload кладётся только внутренний
`resume_path`; frontend отображает CTA, если путь начинается с одного `/`. Цена при продолжении
пересчитывается текущим backend checkout, а закреплённый промокод продолжает жить по своему TTL.

## Влияние

- **БД:** три nullable-колонки и индекс latest-checkout; destructive DDL отсутствует.
- **Безопасность:** provider URL и токены не сохраняются; frontend принимает только относительный путь.
- **Биллинг:** создание и fulfilment платежа не меняются.
- **Совместимость:** старые события получают прежнюю кнопку в каталог.

## Критерии приёмки

- [x] Контекст пишется для Telegram checkout и web/Telegram payment_created.
- [x] Reminder выбирает последний заказ и не затрагивает уже оплативших.
- [x] Telegram CTA восстанавливает plan/device; web CTA — plan/device/method.
- [x] Старые события без контекста используют generic fallback.
- [x] Миграция, backend/frontend unit, lint, build и E2E проходят.

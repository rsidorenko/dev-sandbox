# Design Spec — Упрощение рефералки и FAQ в Telegram-боте

- **Автор / ответственный:** rsidorenko
- **Дата:** 2026-09-02
- **Статус:** approved (пересмотрено 2026-09-02)
- **Связанный plan:** `docs/superpowers/plans/2026-09-02-bot-referral-help.md`

## Контекст и проблема

Экран реферальной программы перегружен двумя ссылками в тексте, таблицей ставок для каждого тарифа
и статистикой, которая не помогает пригласить друга. Главная выгода — бесплатный месяц за первую
оплату друга от одного месяца — теряется среди деталей.

Экран «Помощь» описывает пункты меню вместо ответа на реальные вопросы. Актуальный FAQ уже есть на
лендинге, но в Telegram его нет.

## Цели

- Сделать реферальный экран коротким и сфокусированным на награде +30 дней.
- Дать два понятных способа приглашения: поделиться ботом внутри Telegram и открыть персональную
  веб-ссылку для отправки в любом другом приложении.
- Перенести десять актуальных вопросов и ответов из FAQ фронтенда в интерактивную «Помощь» бота.
- Сохранить HTML-форматирование сообщений и существующую анимацию эмодзи подарка.

## Non-goals

- Не менять правила кешбэка, начисления бонусных дней, реферальные ссылки или схему БД.
- Не создавать отдельную систему контента, синхронизируемую между frontend и backend.
- Не использовать `blockquote expandable` как аккордеон: это цитата, а не блок с отдельным шевроном
  для каждого вопроса.

## Текущее состояние

- `backend/src/app/bot_transport/storefront_ui.py:text_referral_program` показывает сырые ссылки,
  сводную статистику и проценты кешбэка по тарифам.
- `backend/src/app/bot_transport/storefront_ui.py:text_help` содержит статичное описание разделов
  меню вместо FAQ.
- `backend/src/app/bot_transport/runtime_facade.py` отрисовывает `CB_REFERRAL` и `CB_HELP`; ответы
  storefront отправляются в HTML, поэтому менять parse mode не требуется.
- `frontend/src/shared/config/site.ts:siteConfig.faq` — источник десяти актуальных вопроса и ответа.
- `backend/src/app/application/referral_handler.py:ReferralInfo` уже содержит Telegram- и
  веб-реферальную ссылки.

## Предлагаемое решение

Реферальный экран содержит краткое объяснение: за первую оплату приглашённого друга тарифа от месяца
пригласившему добавляются 30 дней. Внизу размещаются URL-кнопки:

- «📨 Пригласить друга в Telegram» открывает `t.me/share/url` с персональной deep-link бота и
  подготовленным коротким текстом;
- «🌐 Пригласить друга без Telegram» открывает персональную веб-реферальную ссылку.

Из текста исчезают сырые URL, детальная таблица процентов, второй уровень и несущественная
статистика. Остаются баланс, число приглашённых друзей и число подаренных дней.

Контент FAQ хранится как неизменяемый backend-каталог, повторяющий текущее содержимое
`siteConfig.faq`.

### Пересмотр UX после проверки в Telegram

Проверка показала, что список кнопок не соответствует ожидаемому формату справки. Обычное
HTML-сообщение с `blockquote expandable` тоже не подходит: оно отображается как цитата, а не как
отдельный раскрывающийся вопрос.

Для приглашения в Telegram пробелы в share URL кодируются как `%20`, а не как `+`. Кнопка
«Пригласить друга без Telegram» использует `copy_text` Bot API и копирует персональную веб-ссылку в
буфер обмена; переход в браузер не происходит.

### Пересмотр: нативный аккордеон Telegram

Пользователь предоставил референс ожидаемого интерфейса: каждый вопрос виден в одном сообщении и
раскрывает ответ по нажатию на шеврон. Это соответствует Telegram Rich Messages с блоками
`InputRichBlockDetails`, а не последовательному тексту, цитатам или inline-кнопкам. В transport
добавляется узкий путь `sendRichMessage` для Help; остальные сообщения и `sendMessage` не меняются.

## Альтернативы

- Оставить ссылки в тексте — отклонено: их неудобно копировать и экран остаётся перегруженным.
- Сделать второй URL кнопкой Telegram share — отклонено: это не даёт отправить ссылку вне Telegram.
- Оставить список callback-кнопок для FAQ — отклонено по результатам пользовательской проверки:
  требуется компактный текстовый справочник, а не навигационный экран.

## Влияние

- **Файлы (предположительно):** `backend/src/app/bot_transport/storefront_ui.py`,
  `backend/src/app/bot_transport/runtime_facade.py`, `backend/src/app/runtime/telegram_httpx_raw_client.py`,
  `backend/src/app/runtime/polling.py`, тесты storefront/runtime facade, spec и plan.
- **Миграции БД:** нет.
- **Безопасность:** персональные ссылки остаются только в URL-кнопках, не логируются и не меняют
  механизм их генерации.
- **Биллинг, retention, VPN-провайдер:** не затрагиваются.

## Открытые вопросы

- Нет: веб-кнопка для приглашения без Telegram согласована пользователем.

## Критерии приёмки

- [ ] Реферальный экран подчёркивает бесплатный месяц и не содержит списка процентных ставок.
- [ ] Отображаются кнопки «Пригласить друга в Telegram» и «Пригласить друга без Telegram» с
  персональными ссылками.
- [ ] «Помощь» показывает все десять вопросов и ответов из актуального FAQ фронтенда в одном
  структурированном сообщении.
- [ ] Каждый вопрос Help раскрывает ответ нативным Telegram details-блоком без callback-запроса.
- [ ] Веб-реферальная ссылка копируется нативной кнопкой Telegram, без открытия сайта.
- [ ] Ответы и клавиатуры покрыты unit- и facade-тестами.
- [ ] `pytest -q`, health check и ruff проходят.

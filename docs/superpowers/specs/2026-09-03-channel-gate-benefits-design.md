# Design Spec — подписка на канал для бесплатных выгод

- **Автор / ответственный:** rsidorenko
- **Дата:** 2026-09-03
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-03-channel-gate-benefits.md`

## Контекст и проблема

Подписка на `@bravada_vpn` уже проверяется перед выдачей трёхдневного
пробного периода. Подарочные дни из рассылок и промокоды можно получить
отдельными путями: кнопкой Telegram-рассылки, ручным вводом промокода и через
личный кабинет. Поэтому неподписанный пользователь способен получить часть
бесплатных выгод в обход условия.

## Цели

- Выдавать пробный период, подарочные дни и применение промокодов в боте и
  на сайте только после подтверждённой подписки на канал, когда флаг
  `TRIAL_CHANNEL_SUBSCRIBE_ENABLE` включён.
- Закрыть как Telegram-, так и веб-пути получения выгод.
- Не помечать подарок полученным и не сохранять промокод, если проверка не
  прошла.
- Дать пользователю понятный путь: перейти в канал и повторить действие.

## Non-goals

- Не менять условия платной подписки, расчёт скидок и погашение промокодов при
  оплате.
- Не превращать уже выполненные операторские начисления дней и реферальные
  выплаты в отложенные подарки: у пользователя нет отдельного действия
  «получить» для этих операций.
- Не добавлять миграции базы данных и новые переменные окружения.

## Текущее состояние

- `backend/src/app/application/trial_channel_gate.py` содержит
  `TelegramChannelMembershipChecker`, флаг и имя канала. Метод
  `is_member` различает подтверждённое членство, отсутствие подписки и
  техническую неопределённость.
- `backend/src/app/bot_transport/runtime_facade.py` активирует триал в
  `_handle_trial_activation`, подарочные дни в
  `_handle_broadcast_days_claim`, промокод рассылки в
  `_handle_broadcast_promo_claim` и принимает ручной ввод в
  `_handle_promo_code_input`.
- `backend/src/app/web_api/profile.py` активирует триал,
  `backend/src/app/web_api/notifications.py` выдаёт бонусы по веб-уведомлениям,
  а `backend/src/app/web_api/promocode.py` применяет промокод в кабинете.
  Все три пути обходят текущий Telegram-гейт.

## Предлагаемое решение

Существующий флаг и проверяющий клиент становятся общим гейтом бесплатных
выгод. Имя флага сохраняется для обратной совместимости с уже развёрнутой
конфигурацией: включение `TRIAL_CHANNEL_SUBSCRIBE_ENABLE=1` распространяется
на триал, подарочные дни и промокоды.

В Telegram обработчик проверяет членство до атомарного клейма дней и до
сохранения промокода. При неподписанном пользователе бот показывает ссылку на
канал и кнопку повторной проверки, которая сохраняет исходную кнопку подарка.
Для ручного промокода бот предлагает подписаться и повторно ввести код.

Для сайта приложение создаёт тот же проверяющий клиент и кладёт его в
`app.state`. Веб-уведомление, активация триала и API применения промокода возвращают
`channel_subscription_required`, пока членство не подтверждено. Интерфейс
показывает это как действие со ссылкой на канал. Для веб-аккаунта без
положительного Telegram ID проверка не может быть доказана и поэтому также
отказывает.

Политика для выгоды — fail-closed: `False`, `None` или исключение
`getChatMember` не позволяют выдать дни или применить промокод. Это не
потребляет бонус: пользователь сможет повторить попытку после восстановления
проверки. Бот должен быть администратором канала для корректной работы
`getChatMember`.

## Альтернативы

- Ограничить только кнопки Telegram-рассылок. Отклонено: личный кабинет и
  ручной ввод остались бы обходом.
- Оставить fail-open при ошибке Telegram API. Отклонено: это нарушает условие
  «только для подписчиков» и позволяет получить выгоду при сбое проверки.
- Создать отдельный флаг для бонусов. Отклонено: потребовал бы ручного
  изменения уже работающей production-конфигурации и дал бы два независимых
  режима одного правила.

## Влияние

- **Файлы:** транспорт бота, UI-каталог бота, Web API промокодов и
  уведомлений, сборка Web API, компоненты кабинета, тесты.
- **Миграции БД:** не требуются.
- **Безопасность:** серверная проверка выполняется до мутаций; кнопка не
  передаёт код промокода и остаётся идемпотентной.
- **Биллинг:** расчёт скидки и баланс не меняются.
- **VPN-провайдер:** выдача дней использует существующий
  `grant_subscription_days` только после прохождения гейта.

## Критерии приёмки

- [ ] Неподписанный пользователь не получает пробный период, дни из рассылки
  и не применяет промокод в боте.
- [ ] Он видит ссылку на `@bravada_vpn` и может повторно проверить подписку;
  после подтверждения первоначальный подарок выдаётся.
- [ ] Веб-клейм и веб-применение промокода не обходят проверку; интерфейс
  объясняет требование и ведёт в канал.
- [ ] Техническая ошибка проверки не меняет claims и promo_applied.
- [ ] При выключенном флаге существующие сценарии продолжают работать.
- [ ] Тесты покрывают Telegram и Web API, а `pytest -q` и release health check
  проходят.

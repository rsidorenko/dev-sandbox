# Design Spec — Дорожная карта роста Bravada (12 → 100 платящих)

- **Дата:** 2026-08-08
- **Статус:** approved (umbrella-спека, источник — обсуждение ChatGPT от пользователя)
- **Тип:** umbrella / roadmap (координирует несколько SDD-слайсов)

## Контекст и проблема

Bravada VPN — 12 платящих пользователей. Нужна предсказуемая система привлечения и удержания,
а не «ещё одна рекламная площадка». Рекламный рынок VPN в РФ под жестким контролем ФАС (переходный
период для Telegram/YouTube до конца 2026). Стратегия — **органическое распространение** и
репозиционирование с «обхода блокировок» на «защищённое сетевое соединение».

Источник требований — обсуждение ChatGPT (16 стратегических пунктов + блок-разбор сайта).
**Важно:** значительная часть предложений — бизнес-операции, а не код. Эта спека честно размечает
каждый пункт по слоям и превращает стратегию в последовательность код-слайсов (SDD).

## Слои

### Слой A — НЕ код (владелец: бизнес/маркетинг). В репозитории не реализуется.
- **A1.** Интервью 12 клиентов (4 вопроса: где узнал / зачем / что главное в выборе / почему платный).
- **A2.** Контент-блог по темам безопасности (публичный Wi-Fi, HTTPS, цифровая гигиена).
- **A3.** Telegram-канал «Bravada Tech» как медиа (не витрина «купи»).
- **A4.** Партнёрский аутрич — CPA-схема с небольшими авторами/сообществами.
- **A5.** Юр. review позиционирования (ФАС, контроль рекламы VPN).
- **A6.** Бюджет: тест каналов → масштабирование лучшего по CAC.
- **A7.** Метрики: **CAC** (стоимость привлечения платящего) и **LTV** — главные показатели.

### Слой B — код, фронтенд (сайт Next.js, `frontend/`)
- **B1.** Лендинг: репозиционирование + конверсия + legal-safety. **(этот цикл)** — отдельная спека
  [`2026-08-08-landing-repositioning-design.md`](./2026-08-08-landing-repositioning-design.md).
- **B2.** Тарифы 1/3/12 как основные, короткие периоды — «под кнопкой» (затрагивает
  `backend/src/app/domain/plans.py` отображение + `widgets/landing/TariffsSection.tsx`).
- **B3.** Блок доверия с реальными отзывами (после сбора 5–7 отзывов — зависит от A1).
- **B4.** Блок «Для каких задач» (публичный Wi-Fi / путешествия / работа / несколько устройств).

### Слой C — код, бэкенд/продукт
- **C1.** Рефералка → «бесплатный месяц за друга» (новая семантика наград; `domain/referral.py`,
  применение к подписке, UI кабинета `features/referral`). Психологически сильнее «87 ₽».
- **C2.** Авто-оффер рефералки в боте через 10–30 мин после оплаты + follow-up
  (`runtime/notification_scheduler.py`, `bot_transport`).
- **C3.** Партнёрская/affiliate-программа: партнёрские ссылки, трекинг, статистика
  (регистрации/пробные/оплаты/сумма), дашборд. Связана с A4.
- **C4.** Воронка-аналитика: события посетитель→регистрация→пробный→активация→оплата→продление→реферал;
  хранение и минимальный отчёт. Кормит метрики A7.

## Последовательность

1. **B1** (этот цикл) — правовая безопасность + конверсия лендинга; быстрый выигрыш, низкий риск.
2. **C4 + A7** — без аналитики нельзя считать CAC/LTV; ставится рано.
3. **C1 + C2** — реферальный движок (главный органический драйвер).
4. **C3** — партнёрская программа поверх реферальной инфры.
5. **B2 → B4 → B3** — оптимизация сайта по данным воронки и отзывам A1.

## Критерии приёмки (на уровне дорожной карты)

- Каждый пункт B/C имеет собственную SDD-спеку и реализуется отдельной короткой веткой/PR.
- Пункты A зафиксированы здесь как рекомендации и не порождают код.
- После B1 на лендинге нет юридически рискованных формулировок («перехват невозможен», «без
  ограничений», «YouTube/Instagram» как оффер) — проверяется grep'ом.

## Открытые вопросы

- Точная экономика годового тарифа для B2 — сверить с `domain/plans.py` перед реализацией.
- Источник отзывов для B3 — сбор через A1.

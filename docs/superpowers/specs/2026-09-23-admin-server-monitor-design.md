# Серверы и подключения в админке

- **Дата:** 2026-09-23
- **Статус:** approved — автономная реализация поручена пользователем.
- **Plan:** `docs/superpowers/plans/2026-09-23-admin-server-monitor.md`

## Контекст
`TrafficStatsScheduler` уже опрашивает StatsService один раз на хост, но ошибки сохраняет только в логах. `bare_xray_traffic_state` не отражает успешный пустой ответ, поэтому его отсутствие не означает недоступность сервера.

## Решение
Аддитивная таблица последнего результата опроса для каждой строки сервера: success/error, checked_at, last_success_at. Существующий сборщик записывает наблюдение без дополнительных SSH/TCP запросов. Ошибка записи мониторинга не прерывает сбор трафика. API выдаёт только allowlist полей сервера и агрегаты трафика за текущие сутки МСК. UI группирует по входному хосту и различает подключения TCP/XHTTP/CDN, активность в подписке, источник и возраст наблюдения. Состояния: данные получены, ошибка опроса, устарели, нет данных. Порог устаревания — максимум 15 минут или 3 интервала коллектора.

## Ограничения и безопасность
Опрос StatsService проверяет доступ к статистике, а не VPN-туннель пользователя. Подпись сообщает эту границу. Никаких ключей, SSH/panel credentials и провижининга при открытии страницы. Нет перезапусков Xray или изменения конфигурации серверов. Хосты показываются только авторизованному админу. История/закрытие инцидентов добавляются отдельным MR.

## Приёмка
- Пустой успешный ответ отражается как успешный опрос; ошибки и stale не зелёные.
- Падение записи мониторинга не ломает сбор/выдачу VPN.
- PostgreSQL миграция повторно применима; auth и отсутствие секретов проверены.
- Таблица адаптивна, фильтры и обновление работают; backend/frontend/CI зелёные.

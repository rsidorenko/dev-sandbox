# Design Spec — Безопасность запуска продуктовых экспериментов

- **Автор / ответственный:** команда Bravada VPN
- **Дата:** 2026-09-19
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-19-experiment-safety-remediation.md`

## Проблема

Production compose включал экспериментальные флаги при отсутствии явной настройки. Резолверы
гейта и длительности продолжали применять treatment после ошибки записи назначения, из-за чего
пользовательский опыт мог расходиться с `experiment_assignments`. Для семидневного триала это
создавало риск последующего сброса окна до трёх дней при первом VPN-трафике.

## Решение

- Все новые экспериментальные и диагностические флаги в production compose выключены по умолчанию.
- Назначение варианта записывается и читается одним SQL statement; возвращается именно persisted variant.
- Ошибка или неизвестное назначение возвращают безопасный control: жёсткий гейт и три дня.
- Текст завершения триала не содержит жёстко заданные три дня; web использует корректное склонение.

## Влияние

Оплата, тарифы и VPN CRUD не меняются. Изменяется только выбор экспериментального поведения и
пользовательские тексты. Уже сохранённые назначения остаются sticky.

## Критерии приёмки

- Флаги без production env имеют значение `0`.
- Ошибка БД никогда не включает soft/7d treatment.
- Существующее назначение возвращается без перераспределения.
- Тексты корректны для трёх и семи дней.
- Backend и frontend проверки проходят.

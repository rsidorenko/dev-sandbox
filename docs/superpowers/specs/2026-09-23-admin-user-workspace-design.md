# Рабочее место поддержки пользователя

- **Дата:** 2026-09-23
- **Статус:** approved — автономная реализация поручена пользователем.
- **Plan:** `docs/superpowers/plans/2026-09-23-admin-user-workspace.md`

## Проблема и текущее состояние
`admin/users/page.tsx` загружает 1000 записей и фильтрует локально. `admin_users.handle_admin_get_user` уже возвращает базовую карточку, промокоды и трафик. Подписка отображается без учёта отдельного срока триала.

## Решение
Параметризованные SQL-фильтры и фасеты по всей базе, стабильная сортировка и страницы по 50 записей. Поиск по Telegram ID и внутреннему ID (почта удалена из системы миграцией 098). URL хранит применённые фильтры/страницу/сортировку, localStorage — сохранённый фильтр и выбор колонок без пользовательских секретов. Карточка по внутреннему ID показывает идентификатор, подписку, устройства, баланс, промокоды, трафик, последние проверки и операторские продления. Диагностика только читает БД: право на доступ, незавершённая ротация, выдача после балансоплаты, свежесть проверки подключения. Явно различать право на доступ и подтверждённую работу туннеля. Существующие действия с подтверждениями сохранить, опасные действия убрать в дополнительное меню.

## Безопасность
Существующая admin-cookie авторизация, CSRF на мутации. Явные списки полей; никакой выдачи UUID, seed, токенов подписки, VLESS-ссылок или сырых ошибок. GET не вызывает provider/provisioning. Нет миграций и изменения бизнес-операций. Общая функция entitlement определяет доступ.

## Приёмка
- Счётчики и фильтры не ограничены первой тысячей; суммы и даты корректны.
- Прямые ссылки, refresh/back и сохранённые фильтры работают.
- Карточка и диагностика доступны только админу; нет секретов в ответах.
- PostgreSQL проверяет trial, удалённые ключи, фильтры, пагинацию и неизвестного пользователя.
- Frontend тесты, build, backend regression, ревью и CI проходят.

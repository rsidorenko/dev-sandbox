# Design Spec — достоверная и защищённая проверка VPN

- **Автор / ответственный:** rsidorenko
- **Дата:** 2026-09-19
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-19-connection-check-safety.md`

## Контекст и проблема

Connection Check сопоставляет IP запроса с DNS-адресами `vpn_servers.server_host`. При полном или частичном сбое DNS отсутствие совпадения может ошибочно записываться как `connected=false`. Для relay/CDN `server_host` может быть входной точкой, а не публичным egress-адресом, поэтому автоматическая атрибуция способна назвать неверный сервер. Публичный speed endpoint не требует subscription token и генерирует до 1 МиБ случайных данных на каждый запрос. В админке серверная таблица скрывает неуспешные проверки и не показывает долю подключений.

## Цели

- Не записывать DNS/configuration uncertainty как реальное отсутствие VPN.
- Сопоставлять запрос только с явно заданным check/egress host.
- Защитить speed endpoint действующим subscription token и убрать генерацию payload на каждый запрос.
- Показывать в админке подключённые и неопределённые проверки с честными знаменателями.

## Non-goals

- Не менять выдачу VLESS-ключей, выбор VPN-сервера и 3x-ui CRUD.
- Не пытаться определить, к какому серверу пользователь хотел подключиться, если egress не обнаружен.
- Не хранить IP пользователя.

## Предлагаемое решение

Добавить в `vpn_servers` поле `connection_check_host`. Для прямых xui/tcp-серверов безопасно и идемпотентно заполнить его текущим `server_host`; relay/CDN/bare-xray оставить без догадок до явной операторской настройки. Resolver сохраняет в результате и настроенные, и ненастроенные активные строки. Совпадение с успешно разрешённым host даёт `connected=true`; отсутствие совпадения даёт `false` только когда все активные check-host настроены и разрешены, иначе `null`.

При `null` result endpoint не создаёт строку `connection_checks`. Speed endpoint переносится на tokenized route, проверяет entitlement и отдаёт срез заранее созданного in-memory payload под существующим rate limit. Серверная статистика агрегирует все проверки, включая bucket «Не определён», и возвращает `connected_checks`/`connected_rate`.

## Влияние

- **Файлы:** application/web API connection-check, admin stats, frontend API/карточка/админка, тесты.
- **Миграции БД:** новая additive/idempotent migration `096`; удаления и блокирующие переписывания отсутствуют.
- **Безопасность:** speed endpoint получает bearer-token и entitlement check; rate limit сохраняется.
- **Биллинг:** только read-only entitlement check, обработка платежей не меняется.
- **VPN-провайдер:** новые данные не участвуют в выдаче/удалении ключей.

## Критерии приёмки

- [ ] Частичный/полный DNS-сбой возвращает unknown и не пишет false check.
- [ ] Relay/CDN без явного check-host не сопоставляется по входному адресу.
- [ ] Speed payload доступен только по действующему token и не генерируется на каждый запрос.
- [ ] Админка показывает connected rate и bucket неопределённых проверок.
- [ ] Миграция идемпотентна; backend/frontend/PG тесты зелёные.

# Разбор оплат и выдачи доступа

- **Дата:** 2026-09-23
- **Статус:** approved — автономная реализация поручена пользователем.
- **Plan:** `docs/superpowers/plans/2026-09-23-admin-payments.md`

## Контекст
Оплата, применение подписки и выдача VPN — разные этапы. Сейчас админка показывает только агрегаты продаж. Данные имеются в ledger/apply records и referral_transactions/balance_access_jobs.

## Решение
Read-only список с периодами1/7/30/90 дней, поиском по пользователю и платежному идентификатору, фильтрами провайдера и «Требует внимания», серверной пагинацией. Раздельные колонки: факт оплаты, применение подписки, выдача доступа. Баланс связывается с job строго по user+idempotency key; ключ не выдаётся клиенту. Внешняя выдача неизвестна: текущая подписка не доказательство выдачи по конкретной оплате. device_topup не требует UC05. Старые балансоплаты без job — нет сведений, не ошибка. Порог задержки pending/неприменённого subscription_activated —10мин.

## Безопасность и ограничения
Admin-auth, GET без мутаций. Нет повторного списания, replay/force apply, провижининга. Не возвращать credentials, description, lease/idempotency keys или raw errors. Валюты не складываются, внешний платёж отделён от баланса. Экран содержит зарегистрированные факты, а не полную историю состояний провайдеров. Миграций нет: ограниченный период и существующие индексы; дополнительные индексы только по измеренной необходимости.

## Приёмка
Реальная PostgreSQL проверяет обе ветки, точную связьjob, неизвестную внешнюю выдачу, device_topup, задержку, auth, фильтры и пагинацию. UI показывает русские статусы, ссылки на карточку, датуМСК и источник. Backend/frontend/build/CI проходят.

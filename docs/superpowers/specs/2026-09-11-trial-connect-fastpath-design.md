# Design Spec — быстрый путь от триала до подключения

- **Автор:** rsidorenko
- **Дата:** 2026-09-11
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-11-trial-connect-fastpath.md`
- **Ветка:** `feat/trial-connect-fastpath`

## Контекст и проблема

После активации триала пользователь попадает в главное меню, затем открывает выбор устройства,
выбирает платформу и проходит до шести отдельных экранов инструкции. При конверсии
`trial → первая оплата` около 2% такой путь откладывает первое полезное действие — реальное
подключение VPN — и создаёт несколько точек отказа до того, как пользователь увидит ценность
продукта.

## Цели

- Сразу после успешной активации триала предложить выбор устройства, не отправляя пользователя
  искать нужный пункт в главном меню.
- Для iOS, Android, macOS и Windows дать основной сценарий на одном экране: установить
  рекомендуемое приложение, скопировать/импортировать подписку и включить VPN.
- Сохранить существующие пошаговые инструкции и поддержку как доступный fallback.
- Сохранить текущие события воронки и отдельно учитывать выбор платформы в новом пути.

## Non-goals

- Не менять цены, длительность триала, тарифы, биллинг и правила подписки.
- Не менять выдачу VLESS, 3x-ui, Reality TLS или содержимое подписки.
- Не сокращать сценарий Smart TV: перенос ссылки между устройствами требует отдельного решения
  (например, QR), поэтому существующая подробная инструкция остаётся основной.
- Не добавлять неподтверждённую deep-link схему Happ. Официальная документация подтверждает
  импорт подписки через clipboard/QR/deep link, но не публикует стабильный формат deep link для
  обычной HTTP-подписки; используем нативную кнопку Telegram `copy_text`.

## Текущее состояние

- `backend/src/app/bot_transport/runtime_facade.py:1112` (`_handle_trial_activation`) после
  выдачи триала возвращает главное меню и предлагает самостоятельно открыть «Мои ключи» или
  «Подключить устройство».
- `backend/src/app/bot_transport/storefront_ui.py:699` (`text_connect_device` и
  `connect_device_keyboard`) показывает отдельный экран выбора платформы.
- `backend/src/app/bot_transport/storefront_ui.py:739` для iOS/Android/macOS добавляет ещё один
  экран выбора Happ/Karing; далее используются шесть пошаговых экранов.
- `backend/src/app/web_api/subscription.py:80` уже поддерживает безопасный серверный редирект
  `?open=karing` для автоимпорта в Karing.
- `backend/src/app/bot_transport/storefront_ui.py:1974` уже использует поддерживаемую ботом
  кнопку Telegram `copy_text`; новый путь может переиспользовать этот контракт.
- `backend/src/app/application/funnel_events.py:68` фиксирует начало настройки, выбор платформы,
  подтверждённое подключение и проблему по callback-кодам.

## Предлагаемое решение

1. Ввести отдельные callback-коды `connect_fast_<platform>` для iOS, Android, macOS и Windows.
   Существующие `connect_<platform>` и пошаговые callback-коды не переименовывать: старые
   сообщения и подробный сценарий продолжат работать.
2. Кнопки основного выбора устройства направить в fast path. Для Smart TV оставить существующий
   callback подробной инструкции.
3. После активации триала вернуть короткое сообщение «выберите устройство» с тем же набором
   платформ и кнопкой главного меню.
4. Fast path отображать одним сообщением:
   - iOS/Android/macOS: ссылка установки Happ, кнопка копирования подписки, три коротких действия;
   - Windows: ссылка установки Karing и существующий HTTPS-редирект автоимпорта;
   - подтверждение «VPN работает», переход к подробной инструкции и поддержка.
5. Перед рендером fast path повторно проверить активную подписку и получить актуальный
   `subscription_url`. При отсутствии доступа/конфига показать существующий безопасный экран,
   не формируя пустую ссылку.
6. Расширить маппинг аналитики: `connect_fast_<platform>` считается событием
   `platform_selected`; существующие `*_yes`/`*_no` остаются подтверждением результата.

## Альтернативы

- Удалить пошаговые инструкции полностью — отклонено: они нужны пользователям, которым не
  помог короткий сценарий, и служат безопасным откатом без релиза.
- Перенаправлять обычную ссылку подписки прямо в Happ — отклонено без документированной и
  протестированной схемы приложения.
- Оставить главное меню после триала и улучшить только тексты — отклонено: это не устраняет
  лишний выбор сразу после момента максимальной мотивации.

## Влияние

- **Файлы:** `backend/src/app/bot_transport/storefront_ui.py`,
  `backend/src/app/bot_transport/runtime_facade.py`,
  `backend/src/app/application/funnel_events.py`, тесты bot transport/funnel.
- **Миграции БД:** нет.
- **Безопасность:** URL берётся только из уже выданного пользовательского конфига; callback не
  содержит токен. Проверка активного доступа сохраняется.
- **Биллинг:** не затрагивается; цены и платежи не меняются.
- **Retention / lifecycle:** не затрагивается.
- **VPN-провайдер:** только чтение существующего конфига; CRUD и формат ключей не меняются.

## Открытые вопросы

- QR-импорт для Smart TV вынести в отдельную фичу после проверки реального сценария на ТВ.
- Deep link Happ можно добавить позднее только после фиксации официального формата и проверки
  на iOS/Android/macOS.

## Критерии приёмки

- [ ] После успешной активации триала пользователь сразу видит выбор устройства.
- [ ] iOS/Android/macOS/Windows открывают одноэкранный fast path с рабочими кнопками.
- [ ] Подробные инструкции для всех платформ остаются доступны; старые callback-коды работают.
- [ ] Пользователь без активного доступа или без конфига не получает пустой/чужой URL.
- [ ] Fast path сохраняет события `platform_selected`, `connection_confirmed` и
  `connection_problem`.
- [ ] Тесты покрывают основной путь, fallback и безопасные ошибки.
- [ ] `pytest -q`, Ruff и `python scripts/run_mvp_repo_release_health_check.py` проходят.

# Design Spec — Понятная и мобильная админ-статистика

- **Автор / ответственный:** команда Bravada VPN
- **Дата:** 2026-09-20
- **Статус:** approved
- **Связанный plan:** `docs/superpowers/plans/2026-09-20-admin-stats-ux.md`

## Контекст и проблема

`/admin/stats` содержит полную продуктовую, рекламную и VPN-аналитику, но оператору
сложно отличить метрики периода от текущих gauge, понять зрелые окна и увидеть, какой
эксперимент реально включён. На телефоне KPI расположены слишком плотно, а таблица
Telegram Ads шириной около 2400 px требует длительной горизонтальной прокрутки.

## Цели

- Пояснить смысл, способ расчёта и диагностическую ценность основных блоков и KPI.
- Показывать runtime-статус всех продуктовых экспериментов рядом с результатами.
- Сделать подсказки доступными по hover, focus и tap.
- На мобильных заменить самые широкие таблицы компактными карточками с главными метриками.
- Улучшить мобильные фильтры, отступы, размеры графиков и горизонтальный скролл таблиц.

## Non-goals

- Не менять SQL-формулы, окна конверсии и рекламную атрибуцию.
- Не давать из UI возможность включать production-флаги.
- Не менять дизайн остальных страниц админки и публичного сайта.

## Текущее состояние

- `frontend/src/app/admin/stats/page.tsx:AdminStatsPage` рендерит KPI, графики, продуктовую
  воронку, эксперименты и Telegram Ads в одном большом компоненте.
- `frontend/src/features/admin/QualitySection.tsx:QualitySection` показывает data health,
  когорты, VPN quality и notification holdout.
- `backend/src/app/web_api/admin_stats.py:handle_admin_stats` возвращает результаты
  экспериментов, но не состояние feature flags.
- Таблицы имеют `overflow-x-auto`, однако Telegram Ads остаётся `min-w-[2400px]` и плохо
  читается на телефоне.

## Предлагаемое решение

Добавить в admin stats API каталог runtime-экспериментов с ключом, типом, статусом,
вариантами и главной метрикой. UI выводит его карточками над результатами, поэтому
исторические экспозиции не выглядят как признак активного теста.

Создать переиспользуемый `MetricHelp`: круглая иконка `i`, desktop-tooltip по наведению
и фокусу, на мобильном — раскрываемая подсказка по тапу. Подсказки объясняют не только
название, но и знаменатель/окно и сигнал, на который стоит смотреть.

Для Telegram Ads и результатов экспериментов на узких экранах использовать карточки
с ключевыми показателями; полные таблицы остаются на desktop. Остальные таблицы получают
touch-scroll и подсказку о горизонтальной прокрутке. KPI на самых узких экранах идут в
одну колонку.

## Альтернативы

- Только добавить HTML `title`: отклонено — не работает предсказуемо на touch-устройствах.
- Полностью переписать dashboard на отдельные страницы: отклонено как слишком большой scope.
- Показывать runtime-флаги только из deployment config: отклонено — API контейнера является
  точнее и отражает реально применённое окружение.

## Влияние

- **Файлы:** admin stats API/types/page, QualitySection, новый MetricHelp и тесты.
- **Миграции БД:** нет.
- **Безопасность:** runtime-статусы доступны только через существующую admin-auth защиту;
  значения секретов не возвращаются.
- **Биллинг:** расчёты не меняются.
- **Retention / lifecycle:** без изменений.
- **VPN-провайдер:** без изменений.

## Открытые вопросы

Нет. Управление флагами из админки намеренно отложено.

## Критерии приёмки

- [ ] Админка показывает, какой эксперимент активен, а какой выключен.
- [ ] Каждый главный блок и KPI имеет содержательную `i`-подсказку.
- [ ] Подсказка доступна мышью, клавиатурой и тапом.
- [ ] На ширине телефона кампании и эксперименты читаются без 2400 px прокрутки.
- [ ] Backend/frontend тесты, lint, typecheck и build зелёные.

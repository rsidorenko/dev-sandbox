# Настоящая ротация VPN-ключей

- Дата: 2026-09-22
- Статус: reviewed
- Основание: поручение исправить подтверждённый аудитом перевыпуск одинаковых ключей.
- План: `docs/superpowers/plans/2026-09-22-vpn-key-rotation.md`

## Проблема

UUID вычисляется только из постоянных user ID и транспорта. Очистка vless_uuid
не влияет на ключи. Повторная выдача возвращает прежние credentials.

## Решение

Добавить nullable vless_key_seed: NULL сохраняет старый алгоритм без изменений.
Случайный seed сохраняется только при явном перевыпуске. Вся генерация ключей,
включая reconcile и операторские утилиты, использует единый алгоритм.
Существующее поле vless_uuid не переиспользовать: оно может содержать старые данные.

Сохранить флаг vless_rotation_pending вместе с новым seed до сетевых операций.
Перевыпуск сначала удаляет старые клиенты по стабильному email на всех серверах,
затем создаёт новое поколение. Ошибка не возвращает SUCCESS и не откатывает seed.
Повтор завершает то же pending-поколение. Пока оно pending, чтение конфигурации
не выдаёт непроверенные ключи. Reconcile возобновляет незавершённую ротацию.

Мутации провайдера и reconcile сериализуются общим advisory lock PostgreSQL;
это исключает воскрешение старого поколения из ранее прочитанного bulk snapshot.
Lock берётся неблокирующими попытками с освобождением connection между ними.
Вложенные вызовы в той же задаче не блокируются повторно. Для тестовых провайдеров
без PostgreSQL применяется локальная блокировка. Ограничение: сетевые мутации
разных пользователей сериализованы; это осознанная цена первого безопасного
варианта, дальнейшая оптимизация требует отдельного тестирования bulk reconcile.

## Влияние

Аддитивная миграция 099, без пересоздания ключей существующих пользователей.
Web и Telegram вызывают общую операцию reissue_user; право, срок и device_count
читаются внутри блокировки. Кэш проверяет поколение перед выдачей результата.
Новые секреты не логируются. Изменение подписочного токена не требуется.

## Приёмка и откат

Тесты: legacy совместимость; новые UUID для всех транспортов; старые credentials
удалены; отказ отдельного сервера; повтор после частичной выдачи; pending после
рестарта; два экземпляра с общим PostgreSQL; пересечение с reconcile; истёкшая
подписка; сохранение срока и устройств. Полный pytest + PostgreSQL, ruff, CI.
Откат на старый алгоритм после реальных ротаций недопустим: исправлять вперёд.
До первого перевыпуска код можно откатить, аддитивные колонки оставить.

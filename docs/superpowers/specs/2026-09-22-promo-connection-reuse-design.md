# Повторное использование соединения при расчёте промокода

PostgreSQL-тест с pool max_size=1 воспроизводит TimeoutError при покупке устройств: транзакция удерживает соединение, а resolver пытается взять второе. При заполненном production-пуле это приводит к взаимному ожиданию запросов.

Репозитории промокодов получают необязательное connection. Общий контекст использует переданное соединение без acquire/release; прежние вызовы по умолчанию продолжают получать соединение из pool. Внутри покупки устройств все чтения промокода и eligibility выполняются на conn транзакции. Погашение после commit сохраняет прежний порядок.

Критерии: покупка с pool max_size=1 завершается с промокодом и без него; цена со скидкой корректна, погашение единственное; все тесты проходят. Миграций нет. Изменения денежной политики и очереди выдачи вне этой задачи.

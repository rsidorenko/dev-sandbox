# Серверные проверки качества VPN

Измеритель выполняет небольшие последовательные HTTPS-запросы к Cloudflare trace через
профили подписки. Никаких автоматических speedtest, смены маршрутов или сетевых настроек.
Результаты за 24 часа доступны в админке серверов отдельно от StatsService и клиентского
`/check`. Отсутствие ошибок в серверной сети не гарантирует работу у каждого провайдера.

## Подготовка одной точки

После применения миграции `103_vpn_quality.sql` выполните внутри backend-контейнера:

```bash
python -m app.observability.vpn_quality --location entry-de --bootstrap --entry-server-id 2
```

По умолчанию команда ничего не создаёт и не вызывает выдачу ключей. ID 2 — пример
проверенного входа этой инсталляции; сверяйте актуальную активную строку перед применением.
SSH использует существующий клиент провайдера и настроенные ключи входного сервера;
нового механизма pinning host key collector не добавляет. На точке нужны `/usr/local/bin/xray`,
`/usr/bin/curl`, `/usr/bin/timeout` и Python 3. Секретные файлы измеритель не создаёт.

```bash
python -m app.observability.vpn_quality --location entry-de --bootstrap --entry-server-id 2 --apply
```

Создаётся **новый** internal web-only аккаунт с отрицательным техническим ID и отдельным
реестром назначения. Выдаются 365 дней штатным бесплатным grant с аудитом. Клиенты,
выручка и платёжный ledger не изменяются. Повторный запуск использует тот же аккаунт,
повторяет provisioning при необходимости, но не добавляет дни. Доступ продлевается
отдельным операторским действием; истечение обрабатывает штатный lifecycle.

После проверки live и durable наличия нового аккаунта на всех физических inbounds:

```bash
python -m app.observability.vpn_quality --location entry-de --bootstrap --entry-server-id 2 --apply --enable
python -m app.observability.vpn_quality --location entry-de
```

Результат `provisioned` означает live-проверку, не заменяет отдельную проверку конфигов
на диске. Успех `complete` означает завершённый цикл: результаты отдельных профилей
смотрите в админке. Проверьте там HTTP/TLS, маршрут и отсутствие ошибок измерителя.

## Регулярный запуск

На сервере приложения установите `scripts/vpn-quality.{service,timer}` в `/etc/systemd/system/`.
Сверьте имя backend-контейнера и location в unit. Запустите сначала один цикл вручную,
затем включите timer:

```bash
systemctl daemon-reload
systemctl start vpn-quality.service
systemctl enable --now vpn-quality.timer
systemctl status vpn-quality.timer --no-pager
```

Общий удалённый дедлайн 180 секунд; каждый дочерний Xray имеет независимый watchdog 20 секунд,
каждый HTTPS-запрос — 10 секунд/4 КиБ. Конфиг Xray идёт через stdin, без UUID в argv/логах.
Collector проверяет только активную identity из служебного реестра; fallback на ключи
покупателей отсутствует. При отмене/обрыве SSH watchdog ограничивает жизнь удалённых процессов.
Advisory lock исключает пересечение циклов одной точки. Незавершённый после аварийного
завершения запуск отображается устаревшим, а не успешным. Повторный цикл безопасен.

## Интерпретация

TLS — время до завершения HTTPS/TLS целевого сайта; TTFB — до первого байта, включая
установление. Это не VLESS handshake отдельно и не ICMP RTT. Неподтверждённая карта
connection_check_host даёт `route_unknown`, не ошибку VPN. Для auto полная активная карта
подтверждает принадлежность выхода сети, а не конкретному auto-пулу. Ошибки измерителя
отделены от ошибок HTTPS и несовпадения ожидаемого выхода. Одна цель не заменяет диагностику
произвольных сайтов и провайдеров; для неё предусмотрены отдельные ручные замеры.

Ожидаемый выход должен соответствовать всем разрешённым IPv4/IPv6 адресам connection_check_host.
Не меняйте карту только ради зелёного результата: сначала проверьте реальную топологию.
Данные хранятся без тел, адресов, ключей и исключений. Автоматическое удаление истории
не включено; политика retention является отдельным операторским решением.

## Откат

```bash
systemctl disable --now vpn-quality.timer
systemctl stop vpn-quality.service
```

Дополнительно выключите точку (`vpn_quality_accounts.enabled=false`) операторским SQL.
Не восстанавливайте старые конфиги Xray и не удаляйте пользовательские ключи.
Служебный аккаунт остаётся под обычным lifecycle; удаление/отзыв — отдельное действие.

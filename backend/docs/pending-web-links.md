# Временные ссылки сайта и безопасная очистка

Новый сценарий: POST `/api/v1/auth/link/request` с `{}` возвращает секретную
`subscription_url` и `expires_at`. Email и старое тело запроса отклоняются.
Миграция 107 обязательна перед обновлением API. Ссылки старых аккаунтов не меняются.
До оплаты нет записи `user_identities`, VPN-ключей и реферального начисления.

## Удаление

Начать оплату можно 48 часов. Попытка оплаты записывается **до** запроса к провайдеру.
Истечение 48 часов блокирует новые заказы, но не удаляет записи с `creating`,
`pending` или `succeeded`. Только подтверждённая отмена/истечение у провайдера
разрешает очистку. Ответ «не найден», таймаут и ошибка проверки не считаются отменой.
Подтверждённая оплата переносит исходный токен в постоянный аккаунт и проходит
существующие UC-04/UC-05. Повторные webhook используют прежнюю идемпотентность.

Порядок запуска из backend в штатном окружении сервиса:

```sh
python -m app.persistence.pending_web_retention
```

Это dry-run: только число записей, которые допускают удаление. Проверить результат,
затем отдельным операторским действием разрешить удаление:

```sh
PENDING_WEB_LINK_DELETE_ENABLE=1 python -m app.persistence.pending_web_retention --delete --interval 60
```

Процесс нужно подключить к штатному supervisor/systemd с перезапуском при сбое.
Удаление не запускается автоматически миграцией или веб-приложением. Нельзя обещать
физическое удаление ровно в 48:00: оно выполняется ближайшим успешным проходом.
Проверки провайдера и выпуск доступа требуют штатных настроек платежей и XUI.
Процесс использует кластерную advisory-блокировку и обрабатывает до 100 записей за проход.

## Платёж с неизвестным результатом

Если процесс завершился между созданием платежа и сохранением его номера,
`creating` остаётся и блокирует удаление. Корреляция `pending_web_attempt` передаётся
провайдеру; проверенный webhook может завершить платёж даже без сохранённого номера.
Для YooKassa attempt_id также является idempotency key. Без достоверного результата
нельзя автоматически считать такой платёж неоплаченным. Оператор сверяет запись
с журналом провайдера, не создавая повторный платёж. Неизвестные записи требуют
разбора; текущий worker не восстанавливает потерянный номер из списка платежей.

## Границы

Очистка касается основной БД: только новых неоплаченных записей и их попыток
(ON DELETE CASCADE). Не запускает удаление существующих VPN-ключей или платных
пользователей. Резервные копии и внешние журналы имеют отдельные сроки; их
размещение и фактическую политику удаления должен подтвердить оператор.

Перед публикацией документов заполнить подтверждённый адрес оператора, перечень
получателей/стран и сроки хранения остальных категорий. Проверить уведомления РКН,
локализацию и трансграничную передачу. Новые редакции лежат в shared/legal и имеют
маршруты архива `/offer/2026-09-30`, `/privacy/2026-09-30`, `/refund/2026-09-30`.
Не изменять архив опубликованной версии; для будущих изменений создавать новую.

Выдача кассового чека требует отдельного решения: текущий YooKassaClient передаёт
технический email в receipt.customer. Это не подтверждает вручение чека покупателю.
До выпуска сценария без email проверить реальную выдачу чека с провайдером.

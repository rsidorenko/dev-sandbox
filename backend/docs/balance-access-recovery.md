# Восстановление выдачи после оплаты балансом

Оплата фиксирует списание, подписку, денежную комиссию и balance_access_jobs одной транзакцией. Ответ provisioning / HTTP 202 означает принятую оплату; повторно платить не нужно. После подтверждения всех настроенных VPN-серверов задание становится done. Если право доступа уже истекло, задание завершается как superseded без активации.

Worker запущен вместе с ServerSyncScheduler отдельным циклом. Интервал между проходами — 30 секунд, backoff отказов — до 300 секунд, lease — 2 минуты. Медленная сеть и общая блокировка провайдера могут задержать попытку. После рестарта истёкший lease позволяет продолжить выдачу, повторного списания и комиссий нет.

## Диагностика без изменений

```sql
SELECT status, count(*) FROM balance_access_jobs GROUP BY status;
SELECT count(*) AS pending,
       min(created_at) AS oldest_created,
       min(next_attempt_at) AS next_attempt
FROM balance_access_jobs WHERE status = 'pending';
```

При длительном pending проверить ошибки balance_access_attempt_failed / balance_access_storage_failed / balance_access_worker_error и доступность настроенных серверов. Частичный успех не закрывает задание: worker повторяет выдачу с актуальным сроком и лимитом из subscription_snapshots.

Не удалять аудит списания и не восстанавливать старый snapshot: это может отменить другую успешную покупку. Не повторять оплату с новым ключом операции. Повтор исходного запроса продолжает существующее задание и соблюдает backoff.

## Откат приложения

Версия до миграции 100 не обрабатывает очередь. Перед таким откатом нужно завершить pending-задания или обеспечить работу совместимого worker. Миграцию и записи очереди сохранять. Автоматического удаления или массового переигрывания исторических платежей нет.

Денежные комиссии транзакционны; бонусные месяцы, уведомления и погашение промокодов пока сохраняют прежние best-effort гарантии.
